# M7 load and scaling evidence

Generated by the opt-in integration benchmark
[`backend/tests/test_load_scaling.py`](../backend/tests/test_load_scaling.py).
The captured measurements are in
[`docs/evidence/final/load-test.json`](evidence/final/load-test.json), with the
pytest output beside it.

## Method

- Four independent 100-order runs: one payment consumer twice, then three
  payment consumers twice. Restaurant, delivery and notification workers stay
  at one each.
- 20 simultaneous FastAPI ASGI requests at most per batch, 100 unique
  idempotency keys per run. All four runs accepted and completed 100 orders;
  the final `tst_` queues were empty.
- Real PostgreSQL and RabbitMQ are used. The test bootstrap recreates and drops
  only `quickbite_test`; messages use the `tst_` prefix. No development orders
  or production queues are touched.
- `ENVIRONMENT=test` sets stage delays to zero. Checkout latency is in-process
  ASGI time and does not include nginx or a remote network. These are local
  regression measurements, not a production capacity claim.
- The same run measured 20-request p95s for restaurant pages, name/cuisine
  search, admin restaurant paging, and a fixture menu against the 2,000
  restaurant / 19,992 item database seeded in the disposable test DB.

## Results

| Payment consumers | Run | Accepted / completed | Pipeline seconds | Orders/s | Checkout p50 ms | Checkout p95 ms |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 100 / 100 | 12.546 | 7.971 | 165.220 | 228.596 |
| 1 | 2 | 100 / 100 | 13.054 | 7.661 | 161.816 | 191.882 |
| 3 | 1 | 100 / 100 | 13.059 | 7.657 | 184.711 | 245.255 |
| 3 | 2 | 100 / 100 | 12.923 | 7.739 | 182.494 | 201.069 |

The three-consumer configuration was not faster in this zero-delay local run.
That is expected to be inconclusive: the workload is dominated by database,
dispatcher, and other single-consumer stages, while the test configuration
removes simulated payment work. The benchmark does not claim linear scaling.
All checkout p95 samples were below the assignment's 500 ms target in this
measured environment.

| Read-only endpoint | p95 ms |
| --- | ---: |
| Restaurant page 1 | 15.872 |
| Restaurant name search | 29.982 |
| Restaurant cuisine search | 20.270 |
| Admin restaurant page | 35.385 |
| Fixture menu page | 24.491 |

The test process peak RSS was 156,868 KiB. The benchmark's recorded host load
average and all raw per-run fields are in the JSON evidence file.

## Reproduction

Start Compose PostgreSQL and RabbitMQ, then run from the repository root:

```bash
cd backend
QUICKBITE_RUN_LOAD_BENCHMARK=1 uv run pytest -q tests/test_load_scaling.py
```

The normal test command skips this longer benchmark. Do not point this test at
the development database; `tests/conftest.py` must be allowed to redirect the
connection to `quickbite_test`.
